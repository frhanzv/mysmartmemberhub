# MySmartMemberHub — API & Use-Case Reference

This is the canonical reference for every HTTP route in the system. It covers:

- The full route → controller → permission → module map.
- Common request / response shapes.
- End-to-end **use cases** (member registration → invoice → payment → approval → receipt → reverse → refund note → LHDN submit / cancel).
- The system settings keys that drive runtime behaviour.

> The application is server-rendered (HTML/Bootstrap) — there is no JSON REST API surface. Routes return either an HTML view, a redirect (303-style), a binary file (PDF / Excel / CSV), or a 403 / 404 error page. Requests use form-urlencoded or multipart bodies with a CSRF token (`csrf_test_name`).

## 1. Auth & sessions

| Method | Path | Controller | Auth | Description |
|---|---|---|---|---|
| GET  | `/landing`                | _closure_             | public      | Public marketing landing page. Logged-in users are redirected to `/`. |
| GET  | `/login`                  | `Auth::loginForm`     | public      | Render split-panel login form. |
| POST | `/login`                  | `Auth::login`         | public      | Body: `login` (email **or** username), `password`, CSRF. Sets session, redirects to `/`. |
| GET  | `/logout`                 | `Auth::logout`        | logged-in   | Clears session. |
| GET  | `/forgot-password`        | `Auth::forgotForm`    | public      | Render password-reset request form. |
| POST | `/forgot-password`        | `Auth::forgot`        | public      | Body: `email`. Issues a `reset_token` and (in real deployments) emails a link. |
| GET  | `/reset-password/:token`  | `Auth::resetForm/$1`  | public      | Render reset form. |
| POST | `/reset-password/:token`  | `Auth::reset/$1`      | public      | Body: `password`, `password_confirm`. |

**Unauthenticated requests** to any non-public route are redirected to `/landing` (not directly to `/login`); the landing page has a "Sign in" CTA that takes the visitor to `/login`.

**Session keys** populated after login: `user_id`, `user_name`, `role_slug`, `role_name`, `permissions[]`. `permissions[]` is cached for the session lifetime; logout or role change clears it.

```

Content-Type: multipart/form-data; charset=UTF-8

name=Ali Bin Test

einvoice_postcode=50000
```

**Side effects**:
1. New row in `members` with auto `MEM-NNNN` generated by `AutoNumber::memberNo()`.
2. **If `module.invoices.enabled = 1`**: a fresh `INV-YYYY-NNNN` row is inserted in `invoices` for the plan price + tax.
3. Audit log row written by `AuditableTrait` (`action='create', entity='members'`).

### Record payment request
```
POST /payments/store
member_id=1            # required
invoice_id=             # optional — auto-matched to oldest open invoice for the member when blank
amount=120.00
payment_date=2026-04-30
method=transfer        # cash|transfer|card|cheque|other
reference_no=TXN-001
proof=@bank-slip.pdf
notes=Bank transfer
```

### Approve payment
`POST /payments/{id}/approve` → updates row to `status='confirmed'`, then **if `module.receipts.enabled`** issues a `RCPT-YYYY-NNNN` PDF and links it back via `payments.receipt_id`. **If `module.invoices.enabled`** flips related invoice to `paid`.

Flash text on success: `"Payment confirmed. Receipt RCPT-YYYY-NNNN issued."` (or `"Payment confirmed. (Receipts module disabled — no receipt generated.)"`).

### Reverse payment (refund)
`POST /payments/{id}/reverse` body: `reason=<string>`.

Side effects:
1. `payments.status = 'reversed'`.
2. Related `invoices.status` flipped from `paid` back to `issued`.
3. **If the original invoice has a validated e-Invoice AND `module.einvoice.enabled = 1`**, a Refund Note is auto-issued via `EInvoiceService::submitRefund()` and a row is appended to `einvoice_documents` with `document_type='refund_note'`.

Flash text on success: `"Payment reversed. Refund Note issued to LHDN."` or `"Payment reversed."` if no validated e-Invoice.

### Dropdown options (configurable selects)

Many forms (member registration, payment recording, plan setup) use the `dropdown_options` table so an admin can extend the choice lists without a code change. Categories are seeded by `DropdownOptionSeeder`:

| Category | Used by | Seed values |
|---|---|---|
| `payment_method`     | `Payments::create` / `edit`             | Cash, Bank Transfer, Card, Cheque, Online, Other |
| `registration_type`  | `Members::create` / `edit` (LHDN buyer) | Individual, Company, Government, Foreign |
| `country`            | `Members` address fields                | 17 ISO-3 codes (MYS, SGP, IDN…) |
| `state`              | `Members` address fields                | 17 LHDN Malaysian state codes (`01`…`17`) |
| `tax_type`           | `Plans::create` / `edit` LHDN tax       | `01`–`05`, `06`, `E` |

`DropdownOptions::store` and `update` accept a magic `category=__new__` value paired with `new_category=<free text>`; the controller normalises the string to `lowercase_with_underscores` before insert. Use `is_active=0` to soft-disable an option without deleting it (forms only render `is_active=1` rows). Sort order ties are broken by `label` ASC.

Body shape for store / update:

```
category    = payment_method | __new__
new_category = optional, only when category=__new__
label       = human-readable
value       = stored / submitted value (e.g. "transfer", "MYS", "06")
sort_order  = integer
is_active   = 1 | 0
csrf_test_name = <token>
```

**Render-time helper** (`app/Helpers/format_helper.php`):

```php
$options = dropdown_options('payment_method'); // [['label'=>'Cash','value'=>'cash'], …]
```

The helper memoises results per-request, so calling it multiple times in the same view doesn't re-query.

## 15. Auto-numbering

| Sequence | Format | Counter key | Resets |
|---|---|---|---|
| Member ID  | `MEM-NNNN`             | `counter.member`         | Never |
| Invoice no | `INV-YYYY-NNNN`        | `counter.invoice.<YYYY>` | Yearly |
| Receipt no | `RCPT-YYYY-NNNN`       | `counter.receipt.<YYYY>` | Yearly |

Counters are atomic — `AutoNumber::*` uses a transaction with `SELECT ... FOR UPDATE` semantics on the settings row.

## 16. End-to-end use cases

### Use case A — first-time member onboarding

1. Super Admin logs in (`POST /login`).
2. `GET /members/create` → `POST /members/store` with `name`, `plan_id`, optional `einvoice_*` LHDN fields.
3. Side effect: row in `members` with auto `MEM-0001`. If `module.invoices.enabled` an `INV-2026-0001` is auto-created.
4. The member receives the invoice (via `GET /invoices/{id}/pdf` or `POST /invoices/{id}/email`).

### Use case B — payment lifecycle

1. Membership Staff records a payment: `POST /payments/store`. If `invoice_id` is left blank, the system auto-matches the oldest unpaid invoice for the member.
2. Finance approves: `POST /payments/{id}/approve`.
   - `payments.status` → `confirmed`.
   - **`module.receipts.enabled`** issues `RCPT-2026-0001` PDF.
   - **`module.invoices.enabled`** flips related invoice to `paid`.
3. Optional: Finance reverses for a refund: `POST /payments/{id}/reverse` with `reason`. If the invoice has a validated e-Invoice and **`module.einvoice.enabled`** is on, a Refund Note is auto-submitted.

### Use case C — LHDN MyInvois submit + cancel

> Requires `module.einvoice.enabled = 1` and a valid `einvoice.environment` (`stub`/`sandbox`/`prod`).

1. `POST /invoices/{id}/einvoice/submit`
   - In `stub` mode: returns `Valid` synthetically with `STUB-UUID-…`.
   - In `sandbox`/`prod`: OAuth2 client_credentials → `submitDocuments` → `getSubmission` poll → IRBM UUID + Long ID.
2. The validated invoice now displays the **VALID** badge, IRBM UUID, public portal URL, and a 72-hour `cancellable_until` countdown. The PDF gains an IRBM block + QR code.
3. To cancel within 72h: `POST /invoices/{id}/einvoice/cancel` with `reason=...`. Outside the window the form is hidden — issue a Credit Note instead (manual flow, future).

### Use case D — disable a module (Super Admin)

1. `GET /settings` → toggle, e.g., **LHDN e-Invoice** → off → save.
2. Result: sidebar links disappear, `/invoices/*/einvoice/*` returns 404, and the LHDN card on invoice show pages is hidden. No data is deleted.

### Use case E — export reporting pack

1. Finance: `GET /reports?month=2026-04` to pick a month.
2. Excel: `GET /reports/export/monthly?month=2026-04` — returns `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
3. Outstanding: `GET /reports/export/outstanding`.

## 17. Schema reference

The full schema is in `app/Database/Migrations/`. Migrations execute in this order:

1. `2026-01-01-000001_InitialSchema` — `roles`, `permissions`, `role_permissions`, `users`, `membership_plans`, `members`, `invoices`, `payments`, `receipts`, `settings`, `audit_logs`, `notifications`, `member_documents`.
2. `2026-04-30-000001_LhdnEinvoice` — adds `einvoice_documents`, LHDN columns on `members`/`membership_plans`/`invoices`/`settings`, widens `payments.status` enum to include `reversed`.
3. `2026-04-30-000002_ModuleToggles` — backfills `module.*.enabled` settings on upgrade.
4. `2026-05-01-000001_AddDropdownOptions` — creates the `dropdown_options` table that backs configurable selects (payment methods, states, countries, registration types, tax types).

`DatabaseSeeder` calls, in order: `RolePermissionSeeder`, `UserSeeder`, `PlanSeeder`, `SettingSeeder`, `DropdownOptionSeeder`. A fresh `db:seed DatabaseSeeder` produces 4 roles, 22 permissions, 4 users, 1 plan, 37+ settings, and 51 dropdown options.

Run them in order:

```bash
php spark migrate            # apply pending migrations
php spark db:seed DatabaseSeeder
# or, fresh start:
php spark migrate:refresh && php spark db:seed DatabaseSeeder
```
